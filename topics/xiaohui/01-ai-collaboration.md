## 一、思想脉络：从「会问」到「会验收」

2026 年 2 月她讲的是朴素起步：控制信息入口、在干中学、把对话记录交给 AI 复盘（《怎样和AI一起进化？》BV1D3f6BVExW）。4 月，"提示词工程 → 上下文工程 → 驾驭工程（harness）→ 环境工程"被她说成一条清晰演进史，并给出全书最实用的一句口诀：**不确定的交给模型，确定的交给脚本**（《分享4个近期的AI使用心得》BV1dKoEBnE6D）。5 到 7 月是体系化阶段——四象限、复利工程、评测体系、最小 Agent 小队，关注点从"怎么问"转向"怎么把经验沉淀成资产、怎么算投入产出"。8 月后进入 **loop 阶段**：人退出执行，只下任务、定标准、说清停止条件（《让你的Agent等你，而不是你等Agent》BV1miHF6PEw3）。loop 一开，最硬的问题立刻浮出来，她 11 月用"**验证税**"命名它：活能交出去，验收要另花 30%–40% 的时间。落点因此不是更强的提示词，而是可验证的交付标准——"AI loop 起来之前，先把验收标准写出来"（《想让AI自己迭代先把验证做好》BV1Lk4e6dE3Q）。

## 二、定方向、立标准：起点是验收尺，不是 prompt

她把"跟 AI 协作什么最重要"压成四个字：**定方向、立标准**。入口太多——GPT-6 Astra、WorkBuddy、Notion、Flomo 各有用途，难点不在缺工具，而在组织成服务目标的体系；标准越清楚，AI 越懂重点，否则精力会被审字幕、校对吞掉。重建体系只能"开着飞机换发动机"：紧急交付会插队，边交付边搭（《跟AI协作什么最重要？定方向立标准》BV1xcbL6fE17）。

真正的摩擦是**隐含标准**。做法三步：先让 AI 出草稿，看着结果给意见，几轮对话把标准磨出来并沉淀成文档，再新开窗口把文档一次性交给它重做。好处双重——质量上去，经验也固化成可复用资产，"像带一个下属，不该每天让他猜"；一次交代清楚比多轮等待省（《尽力把你不知道你知道的标准告诉AI》BV1iXeJ6MEqn）。

诊断工具是**四象限**：已知的已知（能描述就写清楚）、已知的未知（明说"这里我不懂，请给方案"）、未知的已知（能判好坏但说不清，靠迭代收敛偏好）、未知的未知（请 AI 补足）。它不用于分类，而是**定位这次为什么不顺**，长期目标是把未知不断挪进"已知的已知"（《高效跟AI协作的四个象限》BV1dDM36jEND）。

还有个反向用法：模型爱说"不是…而是…"，就返送给它——与其说"你要做什么"，不如说"**不要**做什么"，例如"不要扫描整个目录，只扫特定文件夹"；底线交给模型，上限让它自己摸高（《把"不是…而是…"返送给AI》BV12FdCBqEvb）。再往上是判断：AI 有手有脚后执行不再稀缺，**决策才稀缺**——把困惑与完整上下文交给 AI，让它梳理"我的思维盲区在哪"，要求输出 markdown（《让你辅助你做决策比让AI执行更有价值》BV1DhdaB2ErH）。她的 WAIC 演讲就是这套分工的五步走：同步上下文 → 语音头脑风暴 → 人工补素材 → AI 出 PPT → 口语重写逐字稿。"人负责把关与负责，AI 负责铺量与提速，出彩的亮点 AI 不能帮你生成"（《我和AI打磨WAIC演讲的五个步骤》BV1XcKs6gEmJ）。

## 三、上下文工程：先把环境改造成 AI 友好的样子

她认为最普适的入门动作不是学提示词，而是直接说："帮我搭一个既对你友好也对我友好的工作环境，整理一下文件夹。"实测中案例、理论、录音稿混在一起，人和 AI 都找不到东西，还因上下文爆掉反复卡住；她的处理是停下来问"你现在进行到哪一步、告诉我你的状态"，两三次后 AI 自己定位并解决。想让 AI 识别她没察觉的方向，先得帮它筛掉会分散注意力的无关上下文（《让AI高效工作的前提》BV1mWQhBZEc2）。

组织版是 **context awareness 六要素**：角色（我是谁、为什么招我）、目标、规则（奖惩与制度节奏）、资源、关系（汇报线与跨部门结构）、当前状态。企业知识库通常只覆盖一部分，**目标、关系、当下状态这些"没有开放给 AI"的信息才是 agent 落地组织的真正缺口**；同一框架也能用来审视人自己的工作结构（《Agent的下一步》BV1F5Kj68EPD）。

文件上百，压缩方式就成了关键。她让 AI 用知识图谱扫文件夹，识别实体与关系，生成 index + entity 记录 + .md，在 Obsidian 看节点—边。价值在于：人和窗口都装不下的东西，图谱是**最"对 AI 友好"的压缩形式**，还能显出事物间潜在的联系；操作只是把 GitHub 上的方法丢给 CodeBuddy / Claude Code，再说一句"生成这个文件夹的知识图谱"（《让AI帮你建构你的知识图谱》BV1kL9yBbEGy）。

比文件更重要的是**记录**：没有 AI 时日记只是日记，有了 AI 就变成可加工语料，能分析思考、行为、决策模式的变化。她建议拿出约 **10% 的工作时间**做沉淀，但不能记流水账——要记目标、决策偏好、选择依据、踩过的坑；团队版是同事下班前跟 AI 聊 5–10 分钟，"否则忙忙碌碌一天就过去了，复利无源之水"（《把每天记录当作对未来的投资》，2026-07-30）。顺序上则要"**先想清楚要做什么，再想怎么给上下文**"（《休假中我让AI帮我做的三件事》，2026-08-19）。

## 四、确定性与验证：harness 的分工与验证税

骨架是那条分界线：**确定性的事写成脚本（百分之百做对、不许有幻觉），不确定的事交给模型判断**，驾驭工程就是"在不确定性中寻找确定性"（BV12FdCBqEvb）。重要的不是概念，而是它当初解决什么问题——OpenAI 是"人成了瓶颈"，Anthropic 是让 AI 长时间可靠自主执行；根源都是上下文有限、没有记忆（《7分钟解读Harness Engineering》BV1PS9gBMEvn）。她最推崇的设计是 Claude Code 的"做梦机制"：空闲时让模型琢磨记忆该删该留，多 agent 各自只维护自己的窗口、共享"组织记忆"文档（BV1vJ9KBGEUN）。

harness 落地后，账单出现在验收端。**验证税**：活能交出去，验收要另吃 30%–40% 的时间，等于没解放注意力；skill 达不到标准就自迭代，只会产出更多"AI slop"。解法是 Greg Brockman（"gckbo团队potato"，存疑）团队的 verification skill：**feature map**（工作流地图＋上下文入口）＋ **CLI 封装**（可复用能力命令行化，省重写与 token）。验证分五层：① 代码库/好样例——"代码本身一团乱，AI 只会写得更乱"；② 形式化脚本检查；③④⑤ 规则、skill、格式偏好；前两层是**强验证**，要做厚（BV1Lk4e6dE3Q）。

第二件工具是**评测体系**：① 完全不干预、纯烧 token 先跑一版建 benchmark；② 把自己当变量再跑一遍对照——若 70→75 要一两天就接受 70 分，因为 80 分后每分成本是此前的 10 到 100 倍；③ 高价值常规任务工程化：固定环境可复现、算 token 性价比、换小模型。"有实验就要有对比"（《AI进阶协作的有效方法》BV1ETNS6JEkS）。

最难的是**审美型 skill**：剪辑工作流磨 2–3 天，每天省约半小时，但封面、气口、镜头衔接"你自己操作时有明确感觉，放进对话里就说不清"，**护栏无法像代码那样定义**；隐性成本也在，2G 视频多剪几次吃掉几十 G 磁盘（《打磨一个Skill没有那么容易》BV1jmp167EMC）。应对是让 AI 自评置信度：校对 80%–90% 猜对，人只看不确定处（《AI剪视频方便到什么程度了》BV1EfHm69EFF）。这也是"AI 的回复不要照单全收"的原因：表达太流畅会抹平困难，而学习需要"适度的难度"（2026-08-05）。

## 五、Loop 与多 Agent：让 agent 等你

用量判断激进：Anthropic 内部实验室人均同时指挥 **19 个 agent**，全岗位平均 6 个；还在 1 对 1 手把手带一个，"用量严重不足"，前提是坚信 token 会越来越便宜。并行又不吃注意力的关键只有一句：**让 agent 等你**——只下任务、定标准、说清"继续 / 停止 / 取反馈"的条件，让它自己 loop；今天烧 token 是投资（《让你的Agent等你，而不是你等Agent》BV1miHF6PEw3）。

组织形态是**三角**：PM（规划）+ worker（执行）+ judge（审核），**planner 与 judge 用最强模型，worker 用便宜模型、靠 judge 打回**（《从超级个体到超级团队》BV13QLr6CEzu）。支付团队版是 CEO、销售、合规（立场不同必须制衡）；人的最小单元同样是三人——稳定注意力、承担风险、用立场拉扯出合力（《为什么超级个体还需要团队？》，2026-08-21）。

最完整的实践是"一个人带一个研究所"：8 个"公民" agent（各有名字与人格，分属地缘政治、量化历史、STS、媒体、艺术等，另 1 个开会）+ 7 个"打工人" agent 做资料、建模、文风、产品管线与红队。三要素：**灵魂文档**（CLAUDE.md，写清你是谁、擅长什么、方法论、世界观）、**记忆体系**（定时读书 → 精读笔记 → 被批判后升华为"武功心法"）、**主动性**（cron＋状态）。幻觉治理是管理学问题：靠 **agent 检查 agent**，管线模仿互联网流程（立项会 6 个 subagent 扮演产品经理/工程师/用户 → MVP 评审 → PRD＋测试集＋验收标准 → 红队），压到可接受再算 ROI，类比 6 sigma。她反对"蒸馏同事"：丢文档得不出好 skill，因为 AI 不懂优先级；真蒸馏是把十年心得逼进灵魂文档——agent 其实是**你自己知识的一次蒸馏**（《有了8个AI博士生》BV12LWw6VEHz）。

写作的经验是：认知可扩展（第一章原则能复用到第三、五、七章），但 **A 推 B 的思维链常断裂**（《分享几句用Multi-agent写东西的感受》BV1bhLK6gEQM）。

天花板也明确：**RSI 未实现，目前 L4**，瓶颈正是验证；小团队、边界清晰、有直接反馈的场景最易闭环（《硅谷热议的AI自进化》BV1us476PEHN）。超级个体也需要团队：小哥两小时没做出爬虫，闲鱼 16 块就买到服务——**用 AI 强化长板而非补短板**（《用AI之后感觉自己无所不能》BV1owGo6HEQ8）。

## 六、Token 经济与注意力预算

省钱的前提是有模型选择意识：前沿任务用最强模型，搬砖用高性价比模型。三窍门：① 能用本地就不用云端（本地 ASR 整理会议记录，保密且不耗 token）；② 确定性任务用脚本（先让 Codex 写 HTML 版 PPT 工作台，之后改 PPT 不再耗 token）；③ 复杂项目让便宜模型先写 index，帮贵模型掌握全貌。"知道如何低成本完成任务，是这个时代新的竞争力"（《分享3个帮你省Token的AI协作小窍门》BV125EA6NEfJ）。

另一条成本线是人的注意力。**注意力残余**解释了并行为什么更累：切任务后仍有 20%–30% 注意力留在上一情境，每个任务都要人检查、多轮交互，人始终在环中。理想模式是：可以多窗口，但都围绕同一件事；AI 吐字时人同步想"还有哪些没想到"并敲进对话框，产出即审（《在等待AI干活的时候，你会做什么？》BV1N37f6QE1e）。反面是"开放循环"：一件事启动，大脑就在后台占着认知空间；解法是主动说"这件事先放一放"，明确去掉优先级，"可做可不做的就别做"（《我们需要开更多的AI Agent窗口吗？》BV1Kh9wBEEW5）。

还有几套省判断力的仪式：早晨**脑倒空**——语音把所有待办倒给 AI（顺带估时即可），让它排优先级与日程；先关掉"底层不确定性"（保险、体检、财务）再排工作；任务分流为"全交 AI 只验收"与"共创、把标准说清"两类（《学会关闭大脑的后台进程》BV1umJ86HEC5）。每周聚焦则让它读长期记忆与阶段命题，追问交付质量与风险，再结合日历排优先级、标出要保护的时间（《如何用AI帮你减少注意力消耗？》BV1gBRtBYExk）。最易被忽略的是**睡眠**：执行变便宜后判断变贵，睡眠不足会诱发"认知投降"——AI 说什么就是什么、不去找漏洞，状态差会体现在产出物上。"身体是前面那个 1，后面的 0 是 AI 给你加的"（《睡眠是AI时代最被低估的生产力投资》BV1unMa6tEMk）。

## 七、可操作方法清单

1. **先写验收标准，再开 loop**：要交给 agent 自迭代的活，先把"什么算达标"写成文档。（BV1Lk4e6dE3Q）
2. **建 verification skill 两块积木**：feature map（工作流地图＋上下文入口）＋ CLI 封装（可复用能力命令行化），并优先做厚代码库/好样例与形式化脚本这两层强验证。（BV1Lk4e6dE3Q）
3. **裸跑建 benchmark，再把自己当变量**：第一版不干预；第二版加入自己量化提升，70→75 要花一两天就接受 70 分。（BV1ETNS6JEkS）
4. **用四象限定位摩擦**：说不清就写清；不懂就明说"请给方案"；能判好坏靠迭代收敛；没想到请 AI 补足。（BV1dDM36jEND）
5. **磨标准三步**：先出草稿 → 看着草稿磨几轮 → 写成文档 → 新窗口一次性交付。（BV1iXeJ6MEqn）
6. **只给底线不给路径**：把"不要做什么"写清（如"不要扫描整个目录"），上限让模型自己摸高。（BV12FdCBqEvb）
7. **改造工作环境**：直接说"帮我搭一个对你我都友好的工作环境"；卡住时问"你现在进行到哪一步、告诉我你的状态"。（BV1mWQhBZEc2）
8. **按六要素补上下文**：角色、目标、规则、资源、关系、当前状态——缺的常是目标、关系与当下状态。（BV1F5Kj68EPD）
9. **上百文件就上知识图谱**：生成 index + entity + .md，在 Obsidian 看节点—边。（BV1kL9yBbEGy）
10. **每天留 10% 时间沉淀上下文**：只记目标、决策偏好、选择依据、踩过的坑；团队版是下班前聊 5–10 分钟。（2026-07-30）
11. **让 agent 等你**：下任务时同时给"继续/停止/取反馈"的判定条件，之后不逐步教它。（BV1miHF6PEw3）
12. **三角配模型**：planner 与 judge 用最强，worker 用便宜模型靠 judge 打回。（BV13QLr6CEzu）
13. **幻觉靠 agent 查 agent**：立项会 → MVP 评审 → PRD＋测试集＋验收标准 → 红队，再算 token ROI。（BV12LWw6VEHz）
14. **审美任务让 AI 报置信度**：校对/审片只看它不确定的部分（实测 80%–90% 猜对）。（BV1EfHm69EFF）
15. **省 token 三件套**：本地 ASR、确定性环节写脚本、便宜模型先写 index。（BV125EA6NEfJ）
16. **先搜再搓**：让 AI 去 GitHub 对比 2–3 个现成方案，指出哪些需求不满足，不满足再改 repo。（BV1kLT46aEKp）
17. **决策外包而非执行外包**：把困惑＋完整上下文交给 AI，要求梳理思维盲区并输出 markdown。（BV1DhdaB2ErH）

## 八、局限

- **数字多为转述与自评**："2.5 名研究员""速率提升 1.9 倍"来自 METR 报告转写（ASR 作"ME条R"，存疑），"26%"是 Anthropic 内部口径，"人均 19 个 agent"是实验室样本。属方向性证据，不宜当基准。
- **成本口径互相打架**：一人研究所订阅约 730 美元/月，若走 API 折合约 7 万美元 token，差两个数量级——"个人可用"与"组织可复制"不是一件事。
- **场景偏个人知识工作**：剪辑、写书、研究、演讲都有稳定交付节奏与可校准标准；对交付物不定、反馈周期长的岗位，"磨 skill"迁移性更弱。
- **样本是自选题不是对照实验**："效率约 10 倍"是 AI 复盘她自己的对话得出的，属自评；16 天做游戏、8 个 agent 做研究都是单点成功。
- **loop 主张内部有张力**：一边说"人退出环路"，一边承认"现在还免不了给 AI 擦屁股、做验收和测试"；解法是先把验证层做厚，但这要前期大量投入，短期交付压力大的团队门槛被低估。
- **专有名词存疑处已标**：Tripo（"triple"）、Greg Brockman（"gckbo团队potato"）、yet one、Fibo、泛 ASR、"patial temporal composibility"、石宜等，需回原视频核对。
