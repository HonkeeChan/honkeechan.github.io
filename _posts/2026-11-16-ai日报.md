## 🔥 必读

### 1. 阿里 Qwen4-Max 正式发布：2.4T 总参数只激活 71B，Work360 单任务成本降 58%

Qwen4-Max 是 **2.4 万亿总参数、每 token 激活 71B**，另有 **328B N-gram Embedding** 参数，具备**原生视觉**与**百万 token 上下文**。三处架构改动：**GDN + Qwen Sparse Attention（QSA）** 混合注意力——每四层里三层 Gated DeltaNet 把历史压成固定大小状态，剩下一层 QSA 用轻量索引器以 block 粒度选相关上下文；**Gated Residual** 把残差流扩成四条并行分支、用动态读写门控增强跨层传递；**N-gram Embedding** 在第二层按局部上下文查表补一层 token 模式表示。效果：2.4T 规模下预训练全程无 loss spike，基座在内部知识/代码/问答/STEM 四类评测的**每字节比特数（BPB）比 Qwen3.8-Max 降 5–13%**，同时激活参数再减 25%。

能力与成本是这次的重点。阿里自建的 **Work360** 框架把行业场景拆成 **26 个一级 / 182 个二级 / 721 个三级领域**，Qwen4-Max 得 **52.69 分**（前代 47.74）。在 DeepSWE、AA-Briefcase、HLAB-Vals、BioMysteryBench、HealthBench 等基准上，它拿到高于 **Claude Opus5.5、GPT-6.1 Sol、GPT-6 Astra** 的分数；但报道明确写了短板——在 **Agents' Last Exam、AgentArena** 这类超长时序、开放式智能体任务上仍弱于 Opus 5.5 与 GPT-6 Astra。第三方 **Artificial Analysis 智能指数 43 分**（xhigh），比 Qwen3.8-Max 高 9 分，**比 Kimi K3.1 Pro 的 46 分低 3 分**。成本下降幅度因口径而异：AA 口径单任务成本降约 **11%**，阿里 Work360 口径从 **26.58 元降到 11.16 元（-58%）**；Token 消耗在 Work360 的 xhigh/high 两档分别减少约 24%/35%，Terminal-Bench 4.0 上减少约 48%/49%；缓存命中价 **0.5 元/百万 token**。

工程侧两个可引用案例：三丰智能装备、泛海统联精密的产线场景中，**单个工件加工编程的人工投入从约 475 分钟降到 24 分钟（-95%）**；长任务上推「Live Delivery」——先交可用首版、再逐版迭代，配套开源 **Qwen-Live-Delivery-Plugin**。⚠️ 开源边界要说清：**Max 本身不开源**，阿里只说「Qwen4 系列中小尺寸模型将陆续开源」。

- 判读：这是国产旗舰第一次在**专业 Agent 基准上成片超过 GPT-6 Astra / Opus 5.5**，但同时承认在开放式长任务上落后——即「垂直专业任务爆发力强、开放式复杂任务仍有空间」。与同日腾讯 Hy4 flash 形成一对：一个往上打能力天花板，一个往下压单任务成本。
- 来源：[智东西](https://zhidx.com/p/610623.html)、[机器之心](https://www.jiqizhixin.com/articles/2026-11-16-3)、[官方博客](https://qwen.ai/blog?id=qwen4-max)

### 2. 腾讯混元 Hy4 flash：224B 总参数只激活 12B，单任务 0.2 元、盲测满意度逼平 Claude Haiku 5.5

定位是「把 Agent 任务的单价打到零头」。规格：**总参数 224B（其中 64B 为 Engram 参数）、激活仅 12B**，支持多模态与 **100 万 Token 上下文**，解码速度 **>150 Token/s**。定价是最锋利的一刀：**每百万 Token 输入 0.5 元、输出 2 元**，分别是混元 4 正式版的 **1/12 与 1/9**，缓存命中输入价低至 **0.02 元**。

评测要分口径读。腾讯自建 **WorkIndex**（PPT 制作与修改、文档编辑、表格修复、音视频处理、视觉理解等 8 类日常任务）上，Hy4 flash 得 **42 分**，高于预览版 39、低于正式版 51；平均单任务成本 **0.2 元**（预览版 3.2 元、正式版 5.7 元）。更值得看的是**真实工作盲测**：85 位 WorkBuddy 内部用户对 **27 类 259 项**任务打分，Hy4 flash 满意度 **2.79/4**，几乎追平 **Claude Haiku 5.5 的 2.81**，高于 GLM-5.3-Flash 的 2.53，**低于 DeepSeek-V4.1-Flash-1017 的 3.09**；端到端任务时长中位数 **6.7 分钟为四款最短**，单任务成本 **0.26 元 vs DeepSeek 的 1.2 元**。代价在复杂工程任务上很明显：**Terminal-Bench 4.0 仅 19.2（正式版 44.4）**、ProgramBench 16.0（正式版 30.0）。

智东西的实测给了「能干什么、干不好什么」的具体样本：让它做一首黄仁勋像素小人 MV（50 多个分镜）、一句话造出可玩的简化版《模拟人生5》、搭 3D 网球比赛、调 Blender Python API 做鹈鹕骑车动画（脚本编写 26 分钟 + 渲染 20 多分钟）。结论是**长链路串联工具的能力确实在**（角色设计→分镜→动画代码→导出全跑通），短板也很清楚：画面精细度、审美依赖提示词兜底、复杂几何结构（央视大楼变形）易走形、**缺自检闭环**（字幕与音频没对上，模型自己发现不了）。

- 判读：与 Qwen4-Max 是同日相反方向的两个发布。Hy4 flash 的价值不在「更强」，而在**把日常办公类 Agent 任务的成本压到 0.2–0.3 元**；但 Terminal-Bench 掉到 19.2 说明它不能替代正式版做软件工程。注意「比 DeepSeek 便宜」只说成本，**盲测满意度 DeepSeek 反而更高**。
- 来源：[智东西实测](https://zhidx.com/p/610493.html)、[爱范儿](https://www.ifanr.com/1689653)、[InfoQ](https://www.infoq.cn/article/ejVJGwMvIIvplY8yio5r)

### 3. 华为云发布并「开源」昇腾原生具身世界模型 CloudRobo-WM1.2，称 RoboTwin 2.0 / LiberoPro 2.0 双榜第一

华为云「行业 AI 梦工厂」11 月 16 日发布 **CloudRobo-WM1.2**，主打「世界模型原生动作生成」：不再是「VLM 看图 → 外部策略出动作」的两段式，而是让世界模型直接输出高精度机器人动作。五项技术：① **PPA 多模态世界表征**——不只识别物体，还预判物理交互结果（官方比喻：从「看懂静态照片」到「看懂一场正在发生的 4D 动作电影」）；② **DualAct 双通道动作架构**——世界模型直出动作，另有基于 MOT 的动作专家可灵活定义尺寸，提升后训练效率；③ **多粒度监督数据自适应预训练**——按数据实际有效信息组织监督，兼容「动作标注缺失、部分维度无效、深度缺失、相机视角不完整」的异构数据；④ **本体语义保真跨具身运动建模**——给单臂、双臂、轮式提供统一「动作翻译器」，支持多本体协同学习；⑤ **四种弹性推理模式**（World/Expert Action × Joint/Action-only 组合），按算力与延迟需求切换。官方称在 **RoboTwin 2.0、LiberoPro 2.0 两个评测基准均排名第一**，并给出六大工程能力（仿真冷启动、云原生训练、跨本体适配、持续学习进化、安全运行）。

⚠️ **两处必须标注的限定**：① **榜单成绩是厂商自报**——报道未给分数、对照模型与评测配置，也未提供可复现脚本，「双榜第一」本期无法独立核实。② **「开源」目前查无实物**——两篇报道都写「发布并开源」，但**均未给出仓库地址**；GitHub 上唯一同名仓库 `Barry-Liang/CloudRobo-WM`（2026-11-13 建、3 stars）只有一页 README 与一张框架图，自述「**Work in progress. All code, data, and models will be available soon.**」，即**代码、数据、权重都还没放出来**，是否官方仓库亦未获确认。因此「开源」应表述为**「宣布将开源」**。

- 判读：方向正确且与行业收敛（世界模型直接出动作，绕开「表征与动作两段式」的接口损失），跨本体统一动作空间对多形态部署确有价值。但在仓库放出前，这条应视为**路线公告 + 自报成绩**，不是可复现成果。

### 5. 清华 SkillMaster（NeurIPS 2026）：把「技能自我进化」训进 Agent 自己的策略

现有 Agent 技能体系有个共同缺陷：技能由**外部教师模型、预设规则或辅助模块**创建和更新，执行任务的智能体只学会「用技能」，很少被训练去「改技能」。清华李勇团队（一作：北京中关村学院博士生杨敏）的 **SkillMaster** 把技能管理并入智能体自身策略，与任务执行**联合强化学习**。核心洞察很利：一次技能修改好不好，应看它对后续相关任务的实际影响——**补上知识缺口的修改应让原先失败的任务更容易成功，改进操作策略的修改应让已能完成的任务用更少步骤**，这两类可观测变化就是技能编辑的学习信号。三个组件：① **基于轨迹的技能审视**——把目标、已检索技能、轨迹、最终反馈一起给模型，通过 `propose_skill`/`update_skill`/`keep_skill` 做创建、更新、保留（与任务动作同一策略生成，故技能管理也进入训练）；② **反事实技能效用奖励**——对候选编辑选一组探测任务，分别用原技能库与修改后技能库执行，比较下游变化，只有效用为正的修改才写入持久技能库；③ **DualAdv-GRPO**——任务执行与技能管理奖励尺度不同，分别算优势再分配合并更新同一策略。

结果（底座 Qwen2.5-7B）：**ALFWorld 成功率 98.7%、WebShop 82.0%**，分别比 SkillRL 高 **8.8 / 9.3 个百分点**；SearchQA 总体 **48.0%**。行为分析最有意思：训练早期创建与更新活跃，后期**保留技能比例从 81.25% 升到 97.66%**——模型自发从「补和改」转向「守住已积累的技能」。固定参数、从**空技能库**出发，WebShop 成功率 65.63% → **71.88%**。案例：ALFWorld 冷却任务里，智能体发现旧技能要求「先把物体放进微波炉」与接口不符（加热须在持有物体时执行），依轨迹反馈修订后，相关探测任务的加热环节**从 8 步缩到 2 步**。

- 已核实：仓库真实存在（MIT、2026-05-08 建、2 stars，学术仓库 star 不代表影响力）。局限：仅在 ALFWorld / WebShop / SearchQA 三个结构化环境验证，未涉及开放环境、技能删除、跨智能体共享。
- 来源：[机器之心](https://www.jiqizhixin.com/articles/2026-11-16-4)、[代码](https://github.com/sduyangmin/Skill-Master)

### 6. DeepSeek 因算力不足对 C 端限流：7 天不活跃长对话停用、单次输入缩到约 4 万字

多名用户反馈 DeepSeek App 与网页版开始限额：以「**算力不足**」为由，**不再支持超过 7 天不活跃的长对话**（部分用户显示为 72 小时），单次输入文字上限缩短至**约 4 万字**，并限制每日对话额度——达到上限提示「因服务器繁忙，使用额度已达上限」，另有「内容超长，请删减后再试」「消息数量达到上限，请开启新对话」。智东西实测上传 Anthropic 的 **430 页招股书**后，模型提示只能阅读前 20 页或 1 万 Token。评论区主流反应是「喊话梁文锋：收点钱吧」。

- 判读：与 11-14 期「DeepSeek 开放全家桶应用 API」形成对照——**to D 端收紧免费额度、to B 端开放付费能力**，是同一条算力约束下的两向调节。对日常使用的直接含义：长上下文任务需自行分段，不宜依赖超长单轮输入。

### 7. 豆包工作上线「工作台」：21 个专业场景预配好 Skills 与插件，可自建并分享

字节跳动豆包工作上线「工作台」功能，首批 **21 个专业场景**（金融投研、医疗、教育、创意设计、营销、写作、人力资源、财务行政、求职发展、法律事务、数据分析等）。与普通对话的差别是**技能、工具、插件预先配置好**，用户不必逐项挑选，进入工作台直接开工——从体验上说，每个工作台相当于一个**垂类 Agent 应用**。具体配置：金融投研工作台给公告解读、业绩分析、市场简报、公司研究等入口，并接 **万得、同花顺、国泰海通** 数据插件（需授权终端账号）；医生工作台预配临床指南检索、文献解读、科普与患者沟通材料；教师工作台可一键生成教案课件、把一道题变成可拖动调参的互动实验，并与**学科网**官方合作做资源查找与「题图找相似题」；创意设计工作台覆盖海报/社媒配图/品牌视觉/种草视频，任务开启自动建画布便于对比整理。用户还可自建工作台（命名 + 选技能插件 + 补工作要求与偏好）并分享。已上线豆包工作电脑版与豆包电脑版。

- 判读：这是「**Skill / 插件打包成职业模板**」的产品化路径，与个人 Agent 的 skills 目录逻辑同源，差别在于按职业而非按任务组织。⚠️ 属厂商发布口径，无第三方评测；「业内首个」是自我表述。
