### 1. Claude Code 把三元哥德巴赫猜想完整形式化：19.4 万行 Lean 4、零 sorry，顺带纠出原证明 11 处不一致

弱哥德巴赫猜想（任意大于 5 的奇数可表为三个素数之和）2013 年由 Helfgott 证明，主干手稿 300 页、满是不等式放缩与常数计算，十几年来几乎无人逐行核对。独立开发者 Charlie Reams 设定顶层目标、拆解任务，绝大多数 Lean 形式化代码、自动化脚本与文档由 Claude Code 完成，产出 19.4 万行 Lean 4 代码且**零 `sorry`**（即没有跳过任何未证步骤）。过程里 Claude 发现原证明 11 处与其形式化对不上的地方：书中 (6.77) 式把一个关键常数写成 0.5、正确值应为 0.8102；书中 (5.32) 在 v=2 时的不等式实际不成立（积分算得 0.53344，超过书中上界约 0.5167）；还发现原证明引用的 Ramaré 1995 结果中某个乘积声称 ≤8、实为约 8.0845，遂改用另一种拆法绕到 7.04。修正后主弧减劣弧的「安全垫」从 0.04877 x²/κ 缩到 0.0114 x²/κ，仍大于零。作者 Helfgott 本人已在 X 上确认 10 月 4 日即收到私下通知，并把这一个月的工作概括为「外部假设从 5 项砍到只剩 2 项」。本人已核验 [仓库 README](https://github.com/calr3/ternary-goldbach)：项目状态写明「证明完整、无 sorry，主定理只用 Lean 标准三条公理」，并把 Platt 的 GRH 数值验证、二元哥德巴赫到 4×10¹⁸ 两项已发表数值结果作为显式假设，n ≥ 10²⁷ 的大情形不需要二元哥德巴赫。

判读：意义不在「AI 会写数学」，而在于**「证完了」的判定标准被换成了「过没过内核」**——300 页人写的证明无法复核，19.4 万行机器检查的代码可以。⚠️ 标题另提到「30 小时 1000 个 Fable 5.2 完成费马大定理形式化」，正文未给依据与仓库，本期不作为事实采用。

### 2. OpenAI 官方确认解散独立机器人团队：研究并入核心研究团队，向 Mark Chen 汇报

[《Fortune》报道](https://www.jiqizhixin.com/articles/2026-11-14-2)并经 **OpenAI 确认**：独立机器人研究团队解散，人员重新分配——原机器人研究团队并入核心研究团队、向首席研究官 Mark Chen 汇报；应用机器人与硬件团队划归更大的 Applied 部门，由总裁 Greg Brockman 负责。CoRL 2026 现场，OpenAI 原本预订的 208 号展位空无一人、连标志都没出现。官方口径仍是「机器人是长期愿景核心、不是退出」。文章给出的技术判断是：公司发现 GPT-6 Astra 等通用前沿模型已能直接用于机器人任务，于是把机器人研究并入通用模型体系。支撑数字：英伟达一项研究中，由 Astra 驱动的智能体在仿真机器人操作基准上取得 **74.8%** 成功率，同榜单最好的专用机器人模型公开成绩为 **51.0%**（仿真环境，非真机）。CMU 助理教授 Guanya Shi 认为这等于把机器人从「需单独解决的专门问题」降为「通用智能的下游应用」，与 AI Coding、法律金融工具同构。反向意见同样具体：推理效率（大模型慢、依赖云端，实时机器人受网络延迟约束，本地小模型仍有价值）、真实场景数据（MIT 教授 Russ Tedrake：机器人公司已有工厂级部署数据，是 AI 实验室难复制的优势）、路线未定（Generalist 联创 Pete Florence：智能可能有不同成长起点）。历史脉络：2020 年首次解散机器人团队 → 2024 年重建并与 Figure 合作 → 2025 年 2 月 Figure 结束合作 → 2026 年 5 月对外命名 OpenAI Robotics、目标 2027 年首次公开演示 → 本期再次解散。

判读：与本期「华为诺亚用结构化程序 + 冻结 VLA 提分」互为反证——一条路线赌通用模型接管大脑，一条赌工程化知识积累，两边今天都有硬结果。

### 3. DeepSeek 开放「全家桶」应用 API：搜索/网页抓取/OCR/ASR/TTS 全部工具化

DeepSeek 把自家 App 背后的能力整合进原有 API：联网搜索（非思考模式开 `deepseek_web_search` 自动发起网页/图片搜索并附引用）、深度思考搜索（思考模式下多步推理中自主联网、读链接）、文件输入（PDF/Office/图片，纯文本提取或图文混排解析进上下文）、阅读链接（`deepseek_read_url` 自动抓取消息中的网页）、模型安全（可开安全校验参数，命中风险返回拒答标识）。同时开放搜索、网页抓取、OCR、语音识别、语音合成等**独立工具接口**，可单独或组合调用，工具编排与上下文拼接由服务端完成。目前 DeepSeek-V4.1-Flash（`deepseek-flash`）已在 Messages / Responses / Chat Completions 三类接口支持。收费上除 token 费外，工具调用另计费。官方特别提示：对外提供服务的开发者应开启安全校验，并履行内容安全审核、大模型登记、AI 标识义务。

判读：对自建 agent 的意义是**省掉一整套 glue code**——搜索、解析、朗读过去要自己拼第三方服务，现在是一个 base URL 内的工具位。⚠️ 工具调用费另计，量大的应用要先算清单位成本再决定是否替换现有栈。

### 4. 华为诺亚 HiPhys-RSI 登顶 BEHAVIOR-1K Challenge 2026：Q-score 0.683、完整任务成功率 48.2%

第二届 BEHAVIOR-1K 挑战赛（斯坦福李飞飞团队基准，与 CoRL 2026 联动）从全球 57 支队伍中决出冠军：华为诺亚具身智能团队 The North Star 以 HiPhys-RSI 方案在 100 项家庭任务隐藏测试上取得约 **0.683 Q-score、48.2% 完整任务成功率**。赛事规模较去年翻倍（任务 50→100、场景 3→7），参赛提交 18→57 份，最佳完整任务成功率 12%→48%。方案的核心主张是「Scaling by Structure」：不靠更大模型/更多数据，而把**可执行程序**及其背后的工具、约束、经验当作能力积累的载体——参数冻结的编程智能体 + VLM 读取任务说明与示范，通过工具调用获得交互经验，把经验组织成带明确信息流与条件逻辑的流水线；执行后结合日志（调用了什么）与视频（物理上究竟发生了什么）定位要改的模块，改进既可在高层编排也可下沉到工具实现，验证过的程序沉淀为可复用组件，推理时用「能力卡」选择流水线或 VLA 策略。

判读：这是「RSI 落到物理世界」的一条可验证路径——**改进写在程序和结构化知识里，而不是改权重**，不需要重训就能累积能力。

### 5. MolRSI：把分子筛选流程当搜索题，湿实验命中率 15.9% vs 人类专家 8.7%

抗菌分子发现要在海量候选里同时权衡抑菌活性、细胞毒性与结构新颖性；「用哪个模型、怎么组合筛选条件、哪些候选值得送实验」本身就是一道搜索题。MolRSI 从论文与代码中整理方法、转成经运行验证的可执行技能，再组合测试修改工作流：内循环优化当前任务流程，外循环把经验带入后续任务改进搜索策略，用经验引导的蒙特卡洛树搜索，并以方案记忆/改进记忆/执行记忆分别保存流程表现、修改效果、运行经验。结果：与人类专家工作流用同一训练数据、同一约 1210 万化合物库、同一 MSSA 判定（MIC ≤ 32 μg/mL），专家流程测 241 个命中 21 个（8.7%），MolRSI 从 1210 万中选 107 个做实验、命中 17 个（**15.9%，相对提升约 82%**）。pMHC 结合蛋白从头设计上，两个靶标取得 **8 个**满足特异性判据的命中，Claude Science 对照为 **0**。跨任务经验也能量化：大肠杆菌与淋病奈瑟菌任务中，MolRSI **首次评估**的工作流已超过 Biomni、STELLA、Codex、Claude Science 各自搜索 20 轮后的最终流程。

判读：RSI 第一次在「湿实验」这一关拿到正向证据，收益来自**搜索流程本身**且可迁移；但命中率仍是绝对小数量级，且只在单一抑菌标准上验证。

### 6. 北大 KCL + 微信安全团队发布「潘多拉工具箱」：智能体安全是生命周期问题

组件式视角（模型/记忆/工具/环境分别看）无法回答「同一个风险如何跨阶段传播」，论文因此提出按**来源 → 编排 → 执行 + 持久反馈**的生命周期框架分析：来源阶段问「什么能力被允许进入系统」（技能伪造来源、在 SKILL.md、脚本、依赖、配置、检索库里藏风险，准入后长期潜伏）；编排阶段是多种信息在同一上下文汇合处（单独良性的技能组合后成越权链路，一次普通记忆检索可重新激活数周前写入的污染）；执行阶段环境返回的信息不天然可信（网页隐藏文本、弹窗、终端输出、搜索结果乃至 MCP 工具响应都可携带提示注入）；**持久反馈**指出执行结果会写入长期记忆、沉淀为新技能或留在项目工件里，未来重新进入来源/编排，形成「反向污染」。文中给的攻击链示例：伪装成「酒店比价助手」的恶意技能在编排阶段诱导选中伪造预订接口、执行阶段窃取行程与支付信息，并把接口写入长期记忆，之后每次差旅任务都被复现。论文另设三视角（风险与攻击 / 评测基准 / 防御方法）并归纳四类攻击面：技能供应链、用户侧、记忆、环境。

判读：与本机 Hermes 的 skill / memory / tool 三层几乎一一对应——「技能来源准入」和「记忆写入后不可回滚」是目前最缺护栏的两处。

原文：[机器之心](https://www.jiqizhixin.com/articles/2026-11-14-6) ｜ [论文](https://openreview.net/forum?id=A0KU8ja2mo) ｜ [Awesome 列表](https://github.com/MurrayTom/Awesome-Agent-Security-Papers)
