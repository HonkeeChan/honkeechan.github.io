## 🔥 必读

**1️⃣ WildAWM：合成「一整台电脑」来训练电脑智能体，Qwen3.6-35B-A3B 八个 OOD 榜单平均分 42.84→53.42**

微软研究院、UNC-Chapel Hill、佐治亚理工与东北大学合作（arXiv 2610.26828）。思路与以往「逐个合成工具环境」不同：直接合成**一整台个人电脑**——有 shell、文件系统、浏览器与 email 等 MCP 服务，且 GUI / MCP / CLI 三种接口共享同一份状态，贴近真实 CUA（computer-use agent）可在任意界面操作的情形。

环境生成从虚构人物出发：先定职业、联系人、常去网站与手头在忙的几件事，排成逐日计划，再由 coding agent（GLM-5.2 + OpenCode）按天把计划落进数据库与文件；每天状态独立重放两次、结果完全一致才保留，另有 agent 核对数据与计划是否对得上。最终合成 **36 个人物、640 个世界状态**，最后一平均含 **17 万余条数据库记录、约 50 个本地文件**。任务为跨界面任务（XAI），每道题必须同时用到 GUI、MCP、CLI 三种接口；判分用轻量 verifier，与多 agent judge 多数投票的一致率 95%、Cohen's κ 0.90。

训练：341 道题分 100 SFT / 208 RL / 33 验证，先用 GLM-5.2 的 100 条轨迹热启动，再跑最多 64 步 GRPO，训练 Qwen3.6-35B-A3B 与 Qwen3.5-4B。**结果：35B-A3B 在 8 个训练时完全没见过的 OOD 榜单平均分 42.84→53.42（+10.58）**，其中 ClawEval +16.67、OSWorld-Verified +16.06、WebArena +13.72、CUA-Gym +12.22；WebArena 与 GLM-5.2 打平（67.26），Online-Mind2Web 反超 GPT-5.5（80.77 对 72.22）；4B 模型 21.83→30.04。在自有 33 道验证集上通过率 5.68%→35.98%，已接近 20 倍参数的 GLM-5.2（37.88%）。

⚠️ 两条限定作者自己写明：① 相邻两次工具调用之间切换接口的比例从 18.4% 升到 25.5%，长任务（40–120 步）SFT 多解 9.7 个百分点、加 RL 后 17.0 个百分点，但 **RL 只在 easy/medium/hard 桶提升，teacher 模型也不会的 hardest 桶零提升** ⇒ 作者结论是 RL 只能激发与重排 base model 已有能力；② 环境、任务与模板全由开源模型合成（刻意避免间接蒸馏闭源模型），目前只训到 35B 级。项目已全部开源（GitHub 88 star，2026-09-30 建库）。

**2️⃣ GPT-6 Astra 的机器人能力可能来自专门训练：50 个模型的运动学对照指向「Franka 本体过拟合」**

9 月 3 日 GPT-6 Astra 发布后，机器人圈的演示很扎眼：NVIDIA 把它接进 Isaac Sim 工作流完成拆装演示；Unitree G1 在从未见过的房间里自主整理物品并靠空间记忆取物。社区随即喊出「VLA 已死、通用大模型接管机器人」。但 OpenAI 从未披露训练数据构成，也没说明预训练是否用了专门的机器人数据。

一项社区研究给出了反向线索：研究者对 **50 个开源与闭源模型**做正/逆运动学（FK/IK）测试，要求不调工具、不写代码、直接给出末端位姿或关节角。关键在对照实验——把机器人的 DH 参数换另一台七自由度本体后，**GPT-6 Astra、GPT-6.1 Sol、Gemini Argon 三个模型的输出仍与 Franka Panda 的运动学特征相符**，未按新参数重算。研究者据此判定这三个模型对特定机器人本体存在过拟合：记住的是 Franka 的结构，而非可迁移的运动学规律。

⚠️ 限定必须带：这是**初步探索**（项目 2026-11-06 才建库，4 star），只能作为「训练阶段可能积累过特定机器人知识」的线索，**不能证明** OpenAI / Google 具体用了哪些数据；OpenAI 未回应、也未披露。作者已公开实验代码与推理记录，并称计划扩展到 Unitree G1 等更多本体。

## 📌 值得看

**3️⃣ NeurIPS 2026 Firefly：先在真实 API 上探索、再反向出题，得到 5144 个可验证 tool-call 任务**

RL 训 tool-calling agent 需要数千个「带正确中间调用 + 可验证答案」的任务，而主流 benchmark 每个只给几十到几百题（Tau2-Bench 每领域 50–115、MCPMark 127、MCP-Atlas 500）。据 Epoch AI 行业访谈，实验室买一个 RL 任务通常花 200–2000 美元，独家授权再贵 4–5 倍。

作者的判断是：问题不在「如何生成更好的题」，而在**出题与观察的顺序**。人工标注可靠但不可扩展；纯模拟环境可扩展却偏离真实 API（模型学到的是「怎么和模拟器交互」）；前向合成（先出题再让 solver 解）虽然真实，但 solver 的答案被当成 ground truth，没有任何机制保证正确。Firefly 反过来：先在真实 MCP server 上探索并记录观察 → 用 Tool Graph 做 back-chaining 反推任务 → 配 Retrieval-Augmented Tool-Call Simulator 缓存真实返回，让 RL 完全离线可复现，规避 environment drift 与 rate limit。最终得到 **240 个 server、993 个工具、5144 个可验证任务**。

⚠️ 限定：受算力限制只训了 4B 模型，pass@1 与 pass@16 差距不大，作者推测 30B 以上会受益更多但明说「目前仍是假设」；hard 任务仅占 3.5%；为保证可验证性，筛选阶段排除了有状态与需用户认证的 server（而真实世界里这类工具恰恰很多）。代码与数据以 MIT 开源。

原文：[机器之心 · NeurIPS 2026 | 从「先出题」到「先探索」：重新思考Tool-Calling Agent的训练数据合成](https://www.jiqizhixin.com/articles/2026-11-07-5) ｜ [论文](https://arxiv.org/abs/2605.17558)
