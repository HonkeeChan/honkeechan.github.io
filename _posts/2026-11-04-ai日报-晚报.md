**1️⃣ 腾讯混元 Hy4：首次补齐原生视觉与电脑操作，金融众测开源第一**

腾讯 11 月 4 日发布 Hy4 正式版，近期开源模型权重并发布系统卡片。相比 8 月的 preview，Hy4 显著扩展了预训练与后训练规模，首次引入原生视觉理解与 Computer Use（同时操作命令行与图形界面），并对 Blender、CAD 等专业软件与跨应用长程任务做了专项训练。硬指标上：联合腾讯金融科技 FiT 做了 213 位专家的金融众测（153 位来自外部头部机构、七成有五年以上经验），579 个真实任务中 Hy4 得 3.04 分居开源第一（Kimi K3.1 Pro 2.68、GLM-5.3 2.68、DeepSeek-V4.1-Flash-1017 2.97）；WorkBuddy 平均 83.18 分、任务通过率 96.15%，12 个场景中 9 个国内第一；自建测试里幻觉率从 12.95% 降到 7.2%，猜测导致的错误率从 23.1% 降到 5.6%。定价与 preview 持平：输入 6 元、输出 18 元 / 百万 tokens，缓存命中 0.3 元。它还为下一阶段 RSI 做准备——配合自研科研智能体 Hyra2.0，端到端训练吞吐提升 20.1%，并自动训出多项评测优于官方的小模型。

⚠️ 限定条件两条：一是上述基准多为腾讯自建或联合评测，第三方独立复现尚缺；二是官方自报生物安全能力明显弱于前沿模型（Hy-BioExperimentBench 仅 30.4/100），且智东西实测显示它在 3D 建模的"视觉自检"上仍是短板——企鹅左眼设计反复改不对，直到把参考图放大 4 倍、8 倍才看清。与 GPT-6.1 Sol、Claude Opus 5.5 相比仍有可见差距，"跻身最强开源"是开源区间内的说法，不是全面对标闭源旗舰。

**2️⃣ Anthropic 开源 FlashProve：给模型回答办「防伪身份证」，400B 模型可验证**

Anthropic 开源了基于零知识密码学的「可证明推理」系统 FlashProve：服务商先为一组确定的模型权重生成加密承诺（相当于版本指纹），之后每次请求都附一份 zkSNARK 证明，用户不需要拿到权重、也不需要自己重跑模型，就能用「承诺 + 输入 + 回答 + 证明文件」独立验证这个回答确实由该模型生成。它解决的是「你花钱调用的到底是不是你买的那个模型」——第三方中转站偷换低价模型、推理服务器被篡改、安全评估的测试对象与实际部署不一致，这些场景都因此有了技术核验手段。

实测规模已经推到 400B：测试对象是 Meta Llama 4 Maverick（400B MoE，每 token 实际激活约 17B），单张 NVIDIA H100 每秒可生成约 110 个 token 的证明，每 1024 token 请求的证明文件约 18.78MB，24 线程 CPU 验证一份约 17 秒。优化点是只围绕实际激活的专家算、以及推理完成后再批量事后证明。

⚠️ 必须说清的边界：证明的是「来源」，不是「内容正确」；生成证明的 GPU 时间约为普通 vLLM 推理的 70–95 倍，实时逐请求证明会显著推高成本；目前只支持 1024 token 窗口、整数模型与 Greedy Decoding，远未覆盖所有模型与推理方式。团队用 Lean 形式化验证了协议的完整性、可靠性与零知识性质并以 Apache 2.0 开源，但官方也声明形式化验证不等于实际运行的 C++ 代码获得同等保证，快速验证器与形式化协议之间仍需审计——定位仍是研究原型。

**3️⃣ 普林斯顿 SSoN 空间智能大考：人类 83.3%，最强模型 39.7%，五个低于随机猜**

普林斯顿 AI Lab 推出 Same Space or Not（SSoN）基准：1000 道题、4000 张图，每题给四张静态室内照，其中三张来自同一未改动场景、一张来自编辑后的版本，模型要找出无法与其余三张共存的那张并说明理由。它刻意拿掉了动态交互与动作控制，只考最基础的跨视角空间整合。结果：人类准确率 83.3%，六个 VLM 里 GPT-6 Astra Pro 以 39.7% 领先，其余五个全部低于四选一 25% 的随机基线。

低于随机并非能力下限，而是基准特意构造了「看着像变了、空间上却正确」的强干扰视图——模型能发现外观差异，却判断不了差异是否来自视角变化，于是被系统性带偏。分开看六类编辑：交换与细节变化是模型优势区（Astra Pro 两类均 80%+）；镜像是分水岭（除 Astra Pro 外五个模型全部低于 25%），删除题这五个最高只有 Sol Pro 的 42.57%；移动与旋转是共同盲区，移动最高 27.20%、旋转最高仅 9.54%，而人类两类都在 70% 以上，且明确告知题型后仍不提升。换成 CLIP / ViT / DINOv2 共 17 个视觉编码器按特征相似度挑离群图，准确率只有 16.9%–21.7%，同样全部低于随机。更值得警惕的是，六个模型合计 1368 次「选对」里，29.5% 的解释经不起事实核查（True solve 口径）。

**4️⃣ 国行 Apple 智能 Beta 上手：785 天等来的首版，千问需手动开启**

11 月 4 日起国行 Apple 智能随 iOS 27.3 开发者 Beta 开放测试，12 月随正式版推出。首批功能包括写作工具（含「千问创作」，可按自然语言生成文章、邮件、图像）、视觉智能（「询问」由千问提供视觉理解、「翻译」本地完成、「搜索」默认百度识图）、照片消除、智绘表情、备忘录与通话摘要，以及支持文字输入、理解临时改口、维持上下文的 Siri。关键细节：千问扩展**不默认开启**，需进「设置 > Apple 智能与 Siri > 扩展 > 千问」手动启用并登录；每次向千问发送请求前都要用户同意，Apple 称这些数据不用于模型训练、广告或用户跟踪；百度目前只做识图搜索，不负责 Siri 问答。机型限 iPhone 15 Pro 及以上、iPhone 16 及之后，iPhone 15 / 15 Plus 因只有 6GB 内存无缘；智能内容约占 5.92GB。实测槽点：消除工具偶发闪退、花朵边缘修复痕迹明显、连续使用发热显著；WWDC 2026 宣布的下一代 Siri AI 不在本次范围。

**5️⃣ Codex 11 天写出 13.9 万行新内核，Rocky Linux 10 真跑起来了**

CentOS 创始人之一、Rocky Linux 发起人 Gregory Kurtzer 于 10 月 27 日宣布：用「人类主导的智能体工程」（HDAE）在 11 天内写出约 13.9 万行代码，造出一款以 Rust 为主、独立开发的 x86-64 内核 Ginux，能启动 Rocky Linux 10 并运行 systemd。它不是 Linux 分叉——内存管理、调度器、进程模型、文件系统、网络与设备支持全部从头写，但实现了 Linux ABI，所以现有 Linux 二进制程序可不改直接运行。全过程在**一个**持续运行的 Codex 任务中完成（模型 GPT-5.6 Sol）：人负责愿景、架构、验收关卡与故障解读，Agent 负责「实现 → QEMU 运行 → 测量分析 → 修订 → 回归」的内循环。Kurtzer 说选 Codex 是因为它较少把 token 浪费在支线上，但仍要频繁拉回正轨；他刻意关掉 IDE 强迫自己不手改代码，靠"关卡设得多"纠偏。参照系是 Anthropic 的 Nicholas Carlini 用 16 个并行 Claude 智能体造 C 编译器（约 2000 会话、约 2 万美元、10 万行 Rust）。

**7️⃣ ReTerm：让 Code Agent 从自己的失败里学，9B 模型三项评测均涨 13 分以上**

复旦、港中文 MMLab 与上海交大提出 ReTerm，把「自己遇错 → 自己尝试恢复 → 按恢复成败更新参数」接进同一个训练闭环，走一条由自身错误驱动的 RSI 路径。做法分两段：先构建 ReTerm-10K——收集基础模型自己失败的任务，请更强教师模型示范如何检查问题、修复并完成，筛出约一万条恢复轨迹做冷启动；再上在线强化学习，任务失败后保留当时的环境与操作记录，从同一失败现场出发独立尝试多种恢复办法，由任务验证器判定成败并转化为 RL 信号，模型能力变了产生的新失败又成为下一轮起点。ReTerm-9B 成绩：Terminal-Bench 2.0 从 20.2% 到 34.8%（+14.6）、SWE-bench Verified 45.2%→58.4%（+13.2）、OpenThoughts-TBLite 44.2%→60.6%（+16.4）；换三套运行框架仍保留 6.7–12.4 分增益；AIME 2025 Pass@1 从 73.3% 升到 93.3%。消融最能说明问题：恢复示范 SFT 到 25.8%、标准 GRPO 到 28.0%、ReTerm-GRPO 到 34.8%——专门优化恢复行为在常规 RL 之上再贡献 6.8 分。典型例子是 PyStan：包装好了 `import pystan` 仍报错，标准 GRPO 反复装卸，ReTerm 去查安装路径发现模块在 stan 目录，改用 `import stan` 走出死路。

**8️⃣ Comma：一个工作区只留一条主会话，用决策模型 Jev 维护共享事实清单**

常驻型个人智能体 Comma（前身 Bridge 于 4 月 28 日发布，10 月 1 日正式发布，比 DeepSeek《Super-agent 设计探索》早约一个月）给出了一套完整工程实现。结构上每个工作区只跑一个常驻 Router：群聊、私聊、客户端消息全部进同一条会话共享上下文，具体任务交独立 Worker 会话执行，完成后把结果和来源交回 Router；上下文窗口占满时较早内容被压缩出去，但原始记录完整保留，Router 可以在自己的历史里搜索并读回全文。真正有意思的是「精简工作区」——一份按工作区维护的一句话事实清单，同时进入每个 Router 与 Worker 的上下文，可靠性与时效性交给快速决策模型 Jev 判断：写入前逐条问「这条是否属于工作区内其他 Agent 也需要知道的当前事实」，低于阈值就退回；每轮回复后再问两个独立问题——是否需要更新（对话里是否出现新决定、负责人、状态、约束），以及是否偏离（最近回复与工具调用是否与清单或用户请求矛盾、是否在重复已失败的做法）。团队还披露问法做过对比测试：用反向问法时合适的事实也会得到很高概率、几乎全部更新被拒，改成正向提问才拉开两类内容的差距。
