### 1. 谷歌发布首款决策专用模型 Gemini Decision 1：不生成 Token，单次前向对 1000 个问题打分

谷歌发布首代决策专用模型 **Gemini Decision 1** 与配套 **Gemini Decisions API**。它不走「逐个生成 Token」的路子：在单次前向传播中对开发者预先设定的**封闭选项集**打分，直接返回概率与 0–1 置信度，因此不产生输出 Token，也不需要等一段解释。

结构上支持三类判断并可混用于同一次请求：**是/否判断**（可分别设定成立与不成立的标准）、**多项选择**（2–255 个候选项，返回各候选归一化概率）、**有序评分**（0 起的分级标准，返回加权连续分与各级概率）。单次请求最多 1000 个独立问题、输入上限 256K Token，支持文本、图像、音频、视频、PDF 混排，并可调图像/视频分辨率控制 Token 消耗。

延迟方面，16K 多模态输入下中位计算 **50–100ms**、端到端 **150–250ms**，且问题数从 1 增到 100 延迟基本不变。定价每百万输入 Token **0.10 美元**、输出零计费，约为 Gemini 3.5 Flash-Lite 经 Interactions API 的五分之一（降本约 80%）。谷歌称在路由、推理、排序与多模态基准上领先、校准误差最低；InfoQ 记为 9 项测试 7 项第一、最高准确率 **92.2%**。目前已用于 Gemini Notebook、Stitch，并被谷歌搜索用作 **MCP 工具的安全防护层**，识别对抗性行为。

独立开发者实测：54 次调用、30 条客服工单、8 项多语言任务全部分类正确，100 个判断耗时 **0.41 秒**；已知缺陷是把超出预设范围的输入**强行归入已有类别**。社区评价两极——「实用，但不算创新，价值全看真实速度」。

### 2. Anthropic「玻璃翼计划」被质疑：3.8 万条候选漏洞只修了 217 条

网络安全公司 VulnCheck 于 11-11 发布对 Anthropic **Project Glasswing（玻璃翼计划）** 的成绩单：计划推出 7 个月，Claude 累计挖出 **37,966 条候选漏洞**，但公开台账中标记「已修复」的只有 **217 条**；另有撤回 419 条、重复 **1,654 条**。差距还在扩大——最近两个月候选漏洞暴增近 **1.2 万条**，而修复记录仅新增 15 条；归因于 Anthropic 的 CVE 共 442 个，占 2026 年全球公开 CVE 总量的 **0.5%**。

Anthropic 官方口径不同：截至 11-02，37,966 项候选中 6,376 条经外部安全专家审核、**6,009 条有效**、5,087 条已报给软件维护者、**629 条获得上游补丁**。双方唯一的共识是：**人工验证成了硬瓶颈**。Anthropic 已承认验证能力严重限制审核与披露效率，并于 10-08 推出 **OSS Scanner**——开源维护者主动报名即可让 Claude 免费扫描，报告直接发给维护者，绕过 Anthropic 的人工审核队列。

代价落到维护者身上：curl 维护者 Daniel Stenberg 11 月初又收到 45 份报告，此前已公开的 34 份中 **19 份不构成漏洞、6 份为低危**；他为此改了处理规则，低/中危改为 GitHub 公开讨论以分摊审核，并写下「我们的目标是别被淹死」。但战果确实存在：9 月 Claude 查出 curl 一个 Use-After-Free，特定条件下可致远程代码执行，被他称为多年最严重的漏洞之一。另一个未解问题是补丁——审核一份 AI 补丁的工作量常等于自己重写，且「AI 很擅长添加东西，却意识不到东西也可以被移除」。需注意 VulnCheck 报告同时为自家漏洞情报产品引流。

### 3. Anthropic 支持地区新规 11-12 生效：三条红线看「人在哪、公司在哪、老板是谁」

Anthropic 更新 Supported Regions 与 AUP，**11 月 12 日起生效**。核心是把「地区合规」从看 IP 扩展成三条判定线：

1. **物理位置**——用户在不受支持地区使用即违规，**即使是原本受支持实体的员工**；
2. **注册地/总部**——在不受支持地区注册或设总部的实体及其人员一律禁用，无论本人是否身处受支持地区；
3. **资本与实控**——被不受支持地区的个人或实体**直接/间接持有多数股权或控制权**的实体全面禁用。这条直接针对「去硅谷注册壳公司调 API」的路径。

同时明确**禁止用消费级订阅转发请求**，封杀转卖与代理服务；并引入 **30 天安全监控数据留存**，风控从「瞬时 IP」转向「行为规律」——调用时区、语言特征、多账号并发模式异常都可能触发封禁。新智元援引 Anthropic 招股书称，过去 9 个月有 **5%–7% 的收入来自事后被认定违规的客户**，被认为是上市前清理口径的直接动因。后果按梯度为限速、警告、永久封号。

实践提示：依赖 Claude 官方 API 的自动化流程应提前准备合规替代路径并导出 prompt 与对话记录；第 3 条对「境外主体 + 境内实控」的架构影响最大。

### 4. 清华 + 伯克利开源 uni-robot-agent：给「机器人 Computer Use」一套统一 Harness

清华大学丁宁、刘知远、徐梦迪、周伯文团队联合伯克利 Pieter Abbeel 团队开源 **uni-robot-agent**，为 Robot-Use Agent（RUA）建立统一、模块化的 Harness：分 Agent / Orchestration / Tools / Services / Backends 五层，模型调用统一的感知、运动、技能与任务控制接口，硬件差异由底层适配器吸收——接入新本体主要写适配器，不必改上层 Agent 逻辑；统一语义也让跨本体的交互轨迹能汇入同一数据体系，为跨环境训练铺路。

评测刻意收紧：主实验只给 RGB 图像、相机标定、本体状态与任务指令，**不给深度真值、CAD 资产、隐藏场景标注或验证器反馈**，也不允许联网。RoboDojo 基准上，开放权重模型 Qwen3.8-Flash-Next 配该框架得 **31.39 分**，超过官方此前公布的 GPT-6 Astra + RoboProbe（28.97）；同框架下 GPT-6 Astra 得 **51.90**。真机 19 项任务中，**未经任务专项微调**的 Qwen 得 53.50 分，分别领先微调后的 π₀.₅ 5.75 分、零样本 Dream-1 10 分；GPT-6 Astra 配该框架 **80.50 分**。

### 5. The Trinity：把 RSI 的演化单位从「任务」换成「能力」

深圳无尽递归智能提出全模态全任务递归自我改进框架 **The Trinity**：先建任务树，再从测试轨迹反推每个任务所需的能力，转成**能力树**，沿能力树演化出 Harness 树；由 Creator、Explorer、Evolver 三个角色协作，让环境生成与 Harness 协同进化。作者要回答的是「一百次改进究竟是共同进步，还是一百次互不相干的局部优化」。

四轮 RSI 后，28 个跨模态训练基准平均 **+34.1 分**、18 个未见基准平均 **+26.2 分**；首轮增益最大、后续仍有收益，未见任务随迭代上升（部分任务早饱和、个别回退）。真机迁移初步验证：Unitree G1 在办公室找到风扇旁目标桌并走到可触及位置、AlohaMini2 检查倒扣杯子判断是否藏方块并报颜色位置，成功率均从 **0% → 60%**。
